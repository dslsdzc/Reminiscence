# 《回忆》（Reminiscence）整合包设计文档 v1

> 日期：2026-07-31
> 状态：已确认设计的综合规格。定制机制（统一引擎）与支线细节标注为"待深化"。

## 1. 项目定位与核心哲学

一个 1.12.2 + Cleanroom（Java 21）的巨型整合包：**"小时候在视频里看过、服务器里玩过、朋友家见过的模组，这里全都有——但它们被重新编织成一张网。"**

- 无任务书、无进度追踪器、无弹窗提示
- 进度由**材料卡点**自然产生：想合成 → 缺材料 → 自己探索去哪找 → 火箭 → 行星 → 维度 → 回来
- 玩家只需要做一件事：继续玩下去

## 2. 四层架构总览

## 3. 主线设计（第三层）

### 3.1 星系分层

- **家园系**：主世界 → 月球(0.3 AU) → 火星(1.5 AU) → 小行星带(2.8 AU)——教学链（氧气/重力/燃料/火箭）
- **命运行星**（手工设计 20-30 颗，每颗 = 一个经典维度模组）：暮色星/以太星/阿图姆星/交错星/深渊星/恐惧星/埃里伯斯星/午夜星 + 后续按模组清单扩充
- **程序生成外域**（30-80 颗，种子驱动自动生成）：无名行星、环境参数、资源分布、遗迹、稀有度分级——生成算法放 C 引擎（性能 + 护城河）
- **空间站层**（3 个）：轨道站 / 深空中继 / 外围总站——导航、补给、部分维度入口
- **虚无星系（AOA）**：独立支线星系，极远 AU，跳板链可达，内部按 AOA 原生体系探索——不进主线

规模：手工 20-30 + 生成 30-80 = **50-100+ 行星**。

### 3.2 航行系统（AU 制）

- 距离单位 **AU**（游戏化数值）
- **火箭等级 = 每跳最大航程（AU）**：一级火箭 ≤3 AU，逐级放开——星图是开放图，方向自由，任意已解锁行星为起点，目标在航程内即可跳（一级火箭也能一路跳板链到虚无星系）
- 燃料等级（初级→中级→高级→奇点）：能量密度递增，配方材料散落在不同行星
- 软卡点：燃料/防护装备（配方依赖）
- 空间站中继：航程不足分段飞

### 3.4 材料卡点与可发现性

- **无阶段、无时代**——只有配方依赖（统一引擎接管配方，缺维度材料无法合成）
- **可发现性 = 星图模糊线索 + 世界碎片线索**：
  - 星图：未探索行星显示模糊提示（"富含未知矿物"/"信号异常"/"灵异信号"），探索后具体化
  - 世界碎片：地牢壁画、村庄笔记、角色低语——拼线索
- 不用 JEI 来源标注、不用概率性获取

### 3.5 终局

- 条件：全行星登陆 + 全维度进入 + 全部角色至少成功调度一次
- 纪念碑：**主世界家园，满月之夜**自动生成，刻所有角色名，预设计结构随包发布
- 此后世界不再产生新变化

### 4.1 世界事件系统（事件框架，非固定清单）

事件型内容不独立成星、随时可触发、无任务书提示——事件"降临"而非"被接取"。**设计为注册式框架**：事件注册表 + 调度器（按权重抽事件/触发时机/冲突处理），事件 = 配置 + 钩子（新事件 = 新配置，不动框架）——3 个起点事件，实际会随时增加。

**起点事件**：

| 事件 | 触发 | 过程 | 产出 |
|---|---|---|---|
| 泰坦召唤 | 材料仪式（召唤石+条件）| 泰坦降临 → 猎杀（AI 走 PathService C 层，TPS 保护）| 泰坦材料（装备线）|
| 凋灵风暴 | 终局级仪式（多维材料）| 风暴生成 → 阶段战（可多次）| 风暴核心（终局材料）|
| 感染爆发 | 每 N 游戏日概率触发于程序生成行星 | 生物异变 → 星图"感染信号"线索 → 玩家响应清理 | 净化材料（附魔/药剂线）|

**候选扩展**（框架就绪后随时加）：陨石雨 / 日食 / 血月（与满月纪念碑联动设计）/ 维度裂缝 / 虫潮 / 太空风暴……

联动：事件触发 = 星图异常线索（可发现性系统，无弹窗）；感染爆发时角色可协助；事件不参与终局判定；清感染多 = 爆发少（平衡反馈）。

原则：零强制、无追踪器、发现靠线索、与主线无材料卡点关系（可选加速）、完成度不参与终局判定。

## 6. 定制机制（第二层）

### 6.1 统一计算引擎 = 计算运行时 + 服务框架（已定稿）

C 语言核心 + JNI。**定位：不是固定模块清单，是可扩展计算运行时 + 服务框架**：

```
reminiscence-core (C)
├── runtime/          # 运行时底座：内存池/线程池/统一数据域协议/序列化/ABI 版本
├── framework/        # 服务框架：服务注册表/生命周期/服务间依赖/插件加载
└── services/         # 预估起点（8 个，非上限）：
                      #   graph / formula / aggregate / simulation /
                      #   search / path / generation / encoding
```

- **服务可任意新增**：新模组定制发现新计算形态 → 定义新服务类型 → 注册进框架（预估 8 个，实际只会更多）
- **模组定制 = 算法插件注册**：三层扩展（插件→服务→框架）
- **统一数据域是常量**：无论多少服务，能量/材料/数值统一表示协议不变
- **ABI 版本化**：框架升级不破坏已编译插件
- 参考实现：Power Converters 源码（能量转换参照）
- 预估服务接管范围（起点）：EMC 网络/AE2 路径+能量分配/植物魔力网络/星辉聚能光路/神秘节点灵气网/龙之能量中继/末影导管寻路/热力管道/无尽递归合成/血魔法仪式图；泰坦伤害/龙盾能耗/匠魂公式/冰火龙成长/血魔法转换/星辉速率/机械能耗/EMC 评估；血祭坛叠加/灵气并行刷新；核电堆芯模拟/群峦温湿地质/IC2 电网；JEI 检索/AE2 搜索/匠魂组合；实体寻路/角色导航；行星/矿脉/矿床/结构生成；区块存储编码

### 6.2 联动网络 = 总图（规划蓝图，不落具体实现）

```
统一数据域（引擎）：
  能量域（星光/魔力/Joules/RF/EU 统一表示）── EnergyPipe ── 候选：AE2⇄星光 · 魔力→Mek · IC2⇄热力 · 龙盾←能量
  材料域（维度产物→配方注入/前置）─────── MaterialPipe ── 候选：奇点←暮色 · 血魔法←深渊 · 核电←交错 · 生物←埃里伯斯
  数值域（EMC 等数值调节）──────────────── ValuePipe ── 候选：EMC←阿图姆金线
```

- **总图 = 框架 + 候选关系**，三域三类管道；**不落具体转换率/实现细节**
- 联动逐条落地放在实现阶段：按每个模组定制推进时识别、落地（spec-workflow 任务流）
- 咬合闭环原则：联动形成交叉环（A→B→C→A），无单线最优路径
- 平衡配置表公开（行为），管道实现闭源（数据域内转换）

### 6.4 强依赖设计

定制机制不是可选优化，是引擎经 Mixin 层强制接入。核心缺失/替换 → Mixin 层不加载 → 各定制钩子静默回归原生行为，包退化成普通模组堆。启动自检：核心完整性 + ABI 匹配 → 不符走软校验（提示 + 降级）。

- Herobrine 额外实现七形态切换；另有隐藏第八形态 HIM（终局条件达成后解锁）

### 7.3 调度与界面

- 纯指令调度：`/reminiscence <角色> <指令>`；四种模式：全局广播 / 单角色 / 组合 / 战术（按战斗场景自动分配职能）
- 唯一 UI：**属性面板**（信任度/已获取物/当前能力/位置），按键呼出，不常驻
- 无 HUD、无指挥界面

### 7.4 AI 双模

- 云端：大模型驱动（玩家 API 密钥，**仅存本地配置文件**——玩家文档隐私承诺，实现必须兑现）
- 本地：纯状态机规则驱动（无个性但可用）
- 降级：云端超时/断网自动切本地，行为不中断

### 7.5 成长 = 获取物交付制（星辉魔法式强化）

- 无经验条、无等级、无数值成长
- 每角色 3-5 成长节点（核心能力 1 + 进阶 2-3 + 最终形态 1），每节点 = 一件成长物品（自主线/支线产出），材料+仪式交互交付 → 解锁二元能力
- 53 角色 × ~4 节点 ≈ 200+ 成长物品，全部挂在世界产出上
- 示例：Herobrine ← 幽灵碎片(暮色星)→幽魂传送；303 ← 红石核心(小行星带)→方块操控；Slenderman ← 暗影结晶(深渊星)→精神干扰
- 信任系统：成功任务 +、被伤害 -；低于阈值回归野性需重新遭遇

## 8. 护城河策略（方案 C：源码全公开 + CC BY-NC-ND 4.0）

### 8.1 仓库与许可（2026-07-31 修订：由双仓库闭源改为全公开）

- **单仓库公开** `Reminiscence`（全部源码：C 引擎/Mixin 层/注册窗口/AI 集成/脚本/配置/文档）
- **许可证：CC BY-NC-ND 4.0**（贪婪整合包同款，官方法律文本存 `LICENSE-CC-BY-NC-ND-4.0.txt`）——禁止商业使用、禁止演绎（改后分发）；配合 EULA 禁搬运/禁嵌入其他整合包
- 开发期：私有仓开发（现有 Reminiscence-Core 保留），**发布时转公开**——开发期保护未完成内容，发布即开源
- 无混淆（源码公开混淆无意义）· 无 NDA/CLA（贡献走 DCO：`Signed-off-by` 声明 + inbound=outbound，贡献提交即视为接受项目许可证）· 签名保留（防投毒可选）· 渠道指纹保留（防搬运溯源）· 强依赖保留（拆核心=机制消失，配置/脚本在 CC 下同样不可提取）
- 防线映射：防代码级搬运/洗包 = 强（CC + EULA）；防"思路级借鉴" = 弱（机制/玩法不受版权保护，重写合法——闭源同样防不了法律层面，只是隐藏了实现难度）

### 8.2 三层防线

- **法律**：EULA（禁搬运/逆向/拆包提取，见 `docs-dev/legal/eula.md`——参考贪婪 CC BY-NC-ND + CurseForge 惯例，含版权归属三节：闭源核心/第三方模组/游戏本体）· modlist 逐模组授权标注（CurseForge 要求）· compliance 强制项（AI 实现闭源修改的许可证核查——MIT/Apache 可、GPL 不可）· **合作者 CLA**（转让式贡献协议：财产权归包作者，署名权保留，见 `docs-dev/legal/cla-template.md`——结构参考 Apache ICLA，含财产权转让/署名保留/权利担保/第三方材料声明/专利/无担保/通知义务/适用法律）· **AI 闭源修改版权归属**（原始开源实现版权归原作者+署名保留——合规底线；修改版版权归包作者，EULA 声明）
- **技术**：机制-实现分离（公开 diff 只描述行为）· 强依赖（拆核心=机制消失）· **软校验**（哈希不符 → 提示"非官方修改版" + 机制降级，不拒绝启动）· 渠道指纹（各渠道包嵌不同渠道 ID hash 溯源）· 防逆向（C 引擎 -O2+strip，核心 jar 混淆）
- **流程**：执行者（AI/外包）只接触公开仓 + 单任务 spec · 私有仓双人审查 · 私有 runner 构建闭源产物

### 8.3 私有代码托管模型（GitHub 私有仓 + 构建机）

```
GitHub 私有仓（Reminiscence-Core：C 引擎/Mixin/注册窗口/AI 集成）
  ├─ 访问控制：仅包作者 + 合作者账号（2FA 强制），无关设备不克隆
  ├─ 分支保护 + 双人审查 + CI 泄露扫描（防闭源内容误推公开仓）
  ├─ 构建：GitHub Actions 自托管 runner（大电脑）编译 C 引擎/Mixin 打包
  ├─ 签名：签名私钥存 Actions Secrets，构建产物签名后出网
  └─ 备份：GitHub 多副本冗余 + 定期 age 加密全量导出异地（防账号丢失）
```

- 为什么不用自建内网：家庭台式机是单点故障（硬盘损坏 = 源码丢失），GitHub 私有仓多副本更可靠；保密等级对企业级也足够
- 内网 Gitea/WireGuard 方案**降级为可选进阶**（部署文档保留，不执行）——将来若觉得 GitHub 不够再启用
- 模式 A（内部 AI 会话）：GitHub 私有仓权限 + 数据不泄露四条（加密通道/最小权限/会话隔离/密钥管理）
- 护城河三层齐备：技术（混淆/强依赖）+ 法律（CLA/EULA）+ **访问控制（私有仓权限 + 签名产物）**

### 8.3.1a（废弃内容存档）

- ~~C 核心 OLLVM/Hikari（CFF+BCF+指令替换+字符串加密）~~ 废弃
- ~~Java 层 ProGuard 分层混淆~~ 废弃
- ~~敏感信息零进产物（CI strings 扫描）~~ 降级为常规安全检查（密钥不进仓库，GitHub Secrets）

- 核心实现放 **C native 库**，**OLLVM/Hikari 混淆编译**（-O2 + CFF 控制流扁平化 + BCF 虚假控制流 + 指令替换 + 字符串加密）+ strip：机器码 + 扁平化控制流，逆向成本 >> 重写成本 → 抄袭收益归零
- **分级混淆**：核心算法函数全量混淆；每 tick 高频热路径轻混淆（CFF 影响分支预测，性能损失 10-30%）——混淆后回归 TPS 基线测试
- Java 侧只留薄桥接（JNI 调用壳）+ ProGuard 混淆：反编译可得调用序列，拿不到算法
  - 混淆分层：引擎实现类全量混淆（重命名 + 可选字符串加密）；**Mixin 钩子类不混淆**（字符串引用/refmap 断链风险，且钩子只是 JNI 调用壳）；JNI native 声明不混淆（进阶：RegisterNatives 动态注册后可混淆方法名）；公开 API/ABI 契约名保持（rc_* 系列）
  - 工具链（开源免费路线）：ProGuard（重命名/裁剪基底）→ **SB27-Obfuscator**（MC 社区知名，AES 字符串加密+流程混淆）或 **jar-obfuscator**（轻量 CLI）/ **dProtect**（ProGuard 扩展，字符串+流混淆+MBA）→ 商业最强 ZKM（备选，不优先）
  - 选型基准：[JavaObfuscatorTest](https://github.com/huzpsb/JavaObfuscatorTest) 评测破解成本后再定；完整清单参考 ZygoteCode/Java-Obfuscators-List
  - **强制验证**：混淆后 CI 启动冒烟（Cleanroom 加载 + mixin 应用 + 引擎自测 + TPS 基线）——不通过 = 构建失败
- **敏感信息零进产物**：密钥/内网地址/API key 绝不进二进制（CI `strings` 扫描拦截）；签名私钥只存 Actions Secrets
