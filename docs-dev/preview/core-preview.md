## 一、项目一句话

《回忆》：Minecraft 1.12.2 + Cleanroom 巨型整合包——"小时候在视频里看过、服务器里玩过、朋友家见过的模组，这里全都有，但它们被重新编织成一张网"。1350+ 模组、星系主线（100 行星）、都市传说角色调度（53+1 角色）、全模组定制（统一计算引擎）。

## 二、闭源核心概览

闭源核心 = 包的价值底座，四块：

### 1. 统一计算引擎（C 语言，JNI 桥接）

定位：**可扩展计算运行时 + 服务框架**——不是固定模块清单，是"操作系统"级底座：

```
reminiscence-core (C)
├── runtime/      # 内存池 / 线程池 / 统一数据域协议 / 序列化 / ABI 版本
├── framework/    # 服务注册表 / 生命周期 / 服务间依赖 / 插件加载
└── services/     # 预估起点 8 个：graph/formula/aggregate/simulation/search/path/generation/encoding
```

- 所有模组的计算密集逻辑（EMC 网络、AE2 路径搜索、伤害结算、能耗曲线、并行叠加等）统一接入引擎
- **统一数据域**：能量/材料/数值统一表示——跨模组联动网络的技术基础
- 服务可任意新增（模组定制发现新计算形态 → 新服务类型）

### 2. Mixin 注入层

开源模组改源码（patch 公开）、闭源模组 Mixin 注入（清单机密）——把各模组的核心计算调用替换为引擎服务调用。所有定制机制**强依赖**引擎（拆掉引擎 = 机制消失，包退化为普通模组堆）。

### 3. 运行时注册窗口（研究级组件）

全球首创方向：**模组按需运行时加载**——"遇到哪个加载哪个"。1.12.2 注册表层全是动态数据结构（字符串 ID 注册表），无原理性障碍。三阶段路线：

- 阶段 1：内容域分量 + 解锁重启（保底）
- 阶段 2：注册窗口 MVP（纯物品/配方模组运行时加载验证）
- 阶段 3：全量动态加载（渲染/实体/世界生成）

做成后：模组数量不受启动内存约束，6GB 内存目标从根上解决。学术参考：DSU 动态软件更新研究（Gregersen 集成点框架 / OSGi bundle 模型 / JBoss 无父 classloader 图）。

### 4. 角色调度系统 + AI 集成

53+1 个 MC 圈都市传说角色（Herobrine 七形态 / Red Steve / Entity 303 / Null 等），注册表 + 适配器架构，纯指令调度，云端大模型驱动（玩家 API 密钥，本地状态机兜底），信任系统 + 获取物交付成长（无经验条）。

## 四、协作模式（代码交付制）

- 私有仓 push 权限仅包作者一人（GitHub 无协作者邀请）
- 合作者本地开发 → 交付物（文件/patch）→ 包作者本地审查合并
- 交付物随 CLA 归档（日期 + 内容清单）
- 防逆向：C 核心 OLLVM/Hikari 混淆（控制流扁平化）+ Java 层 ProGuard + 签名出网
