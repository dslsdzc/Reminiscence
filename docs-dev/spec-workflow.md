# 执行者工作指南（spec-workflow）

> 读者：外包开发者 / AI 执行工具。不读其他任何文档，只读这份 + 被分配的任务 spec。

## 1. 什么是任务 spec

一个 spec = 一个可独立验证的模块。你只被分配一个 spec，只做 spec 内的事。

**核心纪律**：本整合包的实现分层——脚本/配置（公开）与核心引擎（闭源）。你的 spec 只会引用公开仓路径。任何提到核心引擎内部的文件都不存在于你的工作区。

## 2. 任务 spec 模板

```markdown
# 任务：<名称>

## 目标
一句话 + 可验证的行为描述（只写"要什么效果"，不写"怎么实现"）

## 边界
允许触碰的文件清单（绝对路径级）——触碰清单外 = 违规，CI 会拦截

## 输入
上游数据/接口（指向已发布文档的具体章节/文件）

## 验收标准
可自动运行的验证命令 + 通过条件
（"构建通过"不够——必须具体到可检查的输出）

## 回退条件
什么情况下允许宣告任务失败并退回（禁止糊一个假完成）

## 交付物
文件清单 + 自检清单勾选结果
```

## 3. 执行者工作流程

1. 领取 spec（一次一个）
2. 只读边界内文件（用文档里的路径，不探索其他目录）
3. 实现
4. 跑验收命令，确认全部通过
5. 填自检清单
6. 提交 PR（附自检结果）

## 4. 违规处置

| 行为 | 处置 |
|---|---|
| 触碰边界外文件 | PR 拒绝 + 标记 |
| 谎报验收结果 | PR 拒绝 + 标记 |
| 在文档/注释中写入核心实现细节 | CI 泄露扫描拦截 + 标记 |
| 三次违规 | 后续任务不再分配 |
