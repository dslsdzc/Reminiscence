# 执行者工作指南（spec-workflow）

> 双模式文档：**模式 A（内部会话）** 用于闭源核心开发（包作者本人或其授权的 AI 会话）；**模式 B（外部执行者）** 用于公开部分（外包/第三方 AI）。
> 读者按自己的模式阅读对应章节。

## 0. 模式选择

| | 模式 A：内部会话 | 模式 B：外部执行者 |
|---|---|---|
| 使用者 | 包作者 / 授权 AI 会话 | 外包开发者 / 第三方 AI |
| 访问范围 | 私有仓 + 公开仓 | 只公开仓 |
| 任务类型 | 闭源核心（C 引擎/Mixin/注册窗口/AI 集成）| 脚本/配置/文档/模组 patch |
| 边界 | 无目录边界，但纪律：**公开产物零私有信息** | 单任务 spec 边界，触碰清单外 = 违规 |
| 会话隔离 | 与公开会话分开工作目录 | 独立会话，无私有仓路径 |

**模式 A 纪律（包作者本人也须遵守）**：公开仓的任何产物（文档/脚本/PR）不得包含私有信息（内部类名、JNI 签名、钩子清单、ABI 结构）。CI 泄露扫描对两种模式一视同仁。

## 1. 什么是任务 spec

一个 spec = 一个可独立验证的模块。你只被分配一个 spec，只做 spec 内的事。

**核心纪律**：本整合包的实现分层——脚本/配置（公开）与核心引擎（闭源）。
- 模式 B：你的 spec 只会引用公开仓路径。任何提到核心引擎内部的文件都不存在于你的工作区。
- 模式 A：你的任务在私有仓内进行；任务产出如进入公开仓，先过泄露检查。

## 2. 任务 spec 模板

```markdown
# 任务：<名称>

## 目标
一句话 + 可验证的行为描述（只写"要什么效果"，不写"怎么实现"）

## 边界
允许触碰的文件清单（绝对路径级）——触碰清单外 = 违规，CI 会拦截

## 输入
上游数据/接口（指向已发布文档的具体章节/文件）

## 验收标准
可自动运行的验证命令 + 通过条件
（"构建通过"不够——必须具体到可检查的输出）

## 回退条件
什么情况下允许宣告任务失败并退回（禁止糊一个假完成）

## 交付物
文件清单 + 自检清单勾选结果
```

## 3. 执行者工作流程

1. 领取 spec（一次一个）
2. 只读边界内文件（用文档里的路径，不探索其他目录）
3. 实现
4. 跑验收命令，确认全部通过
5. 填自检清单
6. 提交 PR（附自检结果）

## 4. 违规处置

| 行为 | 处置 |
|---|---|
| 触碰边界外文件 | PR 拒绝 + 标记 |
| 谎报验收结果 | PR 拒绝 + 标记 |
| 在文档/注释中写入核心实现细节 | CI 泄露扫描拦截 + 标记 |
| 三次违规 | 后续任务不再分配 |

## 6. 贡献声明（DCO，方案 C）

项目采用 CC BY-NC-ND 4.0（源码全公开）。任何贡献（代码/文档/配置）提交即视为接受项目许可证（inbound=outbound）。

- 每个提交须含 `Signed-off-by: <姓名> <邮箱>` 行（`git commit -s` 自动添加）
- 签名声明：本提交由我创作，我有权按其许可发布
- 不签名的提交将被拒绝
