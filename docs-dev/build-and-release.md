# 构建与发布流水线

> 设计依据：spec §8（方案 C）/ §10.5（内存策略）。版本号、渠道指纹、平台适配、发布检查清单。

## 1. 版本号方案

```
包版本：语义化（1.0.0）
核心引擎：独立版本 + ABI 兼容标记（如 "abi-1"）
构建号：CI 自动递增（build-N）
校验：manifest.json 声明包版本 + 引擎版本 + ABI——启动时三方匹配，不符走软校验
```

## 2. 渠道指纹（防搬运溯源）

- 构建时：`pack/manifest.json["channel"] = HMAC-SHA256(渠道名, 私密盐)[0:16]`
- 私密盐存 CI Secrets（仅包作者可注入）
- 每渠道独立构建（CF / Modrinth / 国内各一版，指纹不同）
- 溯源流程：发现搬运包 → 提取 channel → 与各渠道期望值比对 → 定位流出源头
- 清除指纹 = 校验失败（完整性校验联动）——搬运者无法干净去除

## 3. 平台适配

| 平台 | 发布物 | 素材要求 |
|---|---|---|
| CurseForge | modpack project + 版本文件 | 逐模组授权标注（modlist.md 许可证列）· README 适配 · 截图 · 更新日志 |
| Modrinth | modpack 上传（CF 兼容格式）| 同上（许可标注更严）|
| 国内 | 网盘 + 自建渠道（QQ 群/B站简介）| 完整 README + 安装说明 + SHA256 与签名公钥 |

- CHANGELOG.md 统一维护 → 各平台摘取对应段落
- 玩家验证：公开渠道指纹对照表 + 校验说明（pack/core/verify.sh）

## 4. 发布检查清单（顺序执行）

1. compliance 核查：🔒 风险项（Pixelmon/Mo' Creatures/车万女仆/SCP-173/Conquest Reforged）——不过关从发布物移除
2. Cleanroom 启动冒烟：全量档 + 经典档（6GB）各跑一遍
3. 签名（可选防投毒）：GPG 签名产物 + 公钥公开
4. 渠道指纹注入：三版分别构建
5. 更新日志整理
6. 上传 + 公布指纹对照表

## 5. 分量档位（内存策略联动）

- 全量档：1338 模组（推荐 10-12GB）
- 经典档：核心分量（约 700，6GB 目标）
- 精简档：M0+M3+核心辅助（8GB）
- 三档同一构建产物，启动器按档位选择挂载（配置切换，重启生效）
